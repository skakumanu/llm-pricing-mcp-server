Added
  • The zero-dependency STDIO bridge is published as llm-pricing-mcp. Clients that only support command-based servers can add {"command": "npx", "args": ["-y", "llm-pricing-mcp"]} — no clone, no Python, nothing to keep in sync; it forwards each request to the hosted /mcp endpoint

v1.73.5 Oct 22, 2026 Fix
X-Api-Key-Tier no longer raises an anonymous caller's rate limit
Changed
  • The tier header is self-declared, and the limiter used to honor it from anyone — an anonymous request could send X-Api-Key-Tier: enterprise and get 600/min instead of the 60/min default. It is now honored only when the request also carries the valid global MCP_API_KEY; anonymous requests always use the default bucket
  • Billing API keys are unaffected — their tier has always come from the billing record, never the header
  • Deployments without MCP_API_KEY configured: the header is ignored there too, since there is nothing to verify it against
v1.73.4 Oct 20, 2026 Fix
Four Azure OpenAI prices restored — the drift check was comparing against the wrong tier
Fixed
  • The reference registry added per-region entries (azure/eu/…, azure/us/…) for gpt-4o, gpt-4o-mini, o1 and o3-mini at Azure's Data Zone tier — exactly 10% above Global Standard. v1.73.0 Oct 17, 2026 Feature
New npx -y llm-pricing-mcp — STDIO access with no clone, no Python
Added
  • New npm package llm-pricing-mcp (npm/llm-pricing-mcp in this repo) — a zero-dependency Node.js bridge for MCP clients that only support command-based STDIO servers, not a direct remote/HTTP url config
  • It holds no tool logic or pricing data of its own: each stdin line is forwarded as-is to the hosted POST /mcp endpoint and the JSON-RPC response is written back to stdout, so it has nothing to keep in sync as tools or pricing change server-side
  • Add to any STDIO-only client config: {"command": "npx", "args": ["-y", "llm-pricing-mcp"]} — no git clone, Python, or pip install needed
  • Concurrent requests are dispatched independently, so one slow tools/call never blocks other in-flight requests from completing first
  • Existing options — the direct remote url config and running mcp/server.py locally — are unchanged; this is a third, lower-friction path for STDIO-only clients, not a replacement

v1.72.0 Sep 12, 2026 Feature
New import_session_usage tool backfills a session's usage after the fact — plus org-wide estimated-usage visibility
Added
  • New MCP tool import_session_usage accepts a batch of usage entries under one shared session_id in a single call — the retroactive counterpart to record_usage, for a session (e.g. a VS Code Copilot Chat session) that wasn't instrumented live. Each entry resolves its input/output tokens from an exact count when known, or estimates them from raw turn text using this server's existing token counter
  • Cost for every entry is computed server-side from current pricing, exactly like record_usage — never trusted from the caller
  • A malformed entry (no usable tokens/text, or a model name that doesn't resolve) is reported as its own per-entry failure without discarding the rest of the batch; the response includes a per-entry outcome plus an aggregate summary (recorded exact / recorded estimated / duplicates / failed)
  • Idempotent like record_usage: when a caller omits request_id, a deterministic one is derived so resubmitting an identical batch is safely a no-op
  • Usage recorded this way is immediately readable through the existing analyze_session_usage tool and GET /usage/session/{session_id} — no change to how either is invoked
  • analyze_session_usage / GET /usage/session/{session_id} and get_usage_summary / GET /usage/summary now also report has_estimated_usage and estimated_request_count, so both session-level and org-wide views surface how much of the reported usage is estimated vs. exact
v1.71.1 Sep 11, 2026 Fix
Session-usage recommendations now warn about quality/cost tradeoffs too
Fixed
  • analyze_session_usage and GET /usage/session/{session_id} could recommend switching to a materially lower-quality model purely because it's cheaper, showing a dollar savings figure with no indication that quality was being traded away — the equivalent recommend_model caveat never made it to this shared code path

v1.71.0 Sep 10, 2026 Feature

Added
  • When a description's task type is auto-inferred (not passed explicitly) and lands on the "chat" fallback, but the text also contains reasoning- or code-generation-style language, the response now includes a caveats entry naming both the inferred category and the plausible higher-stakes alternative — a nudge to double-check with an explicit task_type rather than a silent misclassification
